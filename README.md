## 关注方向

- 把模糊想法慢慢拆成能推进的需求和方案
- 把流程理顺，让协作别总靠“你应该懂我意思吧”
- 用工具、脚本和自动化把重复事情处理得更省心
- 从一个念头出发，尽量把它推到 Demo 或可用版本

## 工作方式

- 从业务目标出发，明确问题边界与优先级
- 用文档、原型和流程图把“差不多懂了”变成“真的对齐了”
- 遇到合适的场景，会把抽象需求继续做成工具、脚本或轻量实现
- 比较在意闭环这件事：不只提出想法，也想看到它真正跑起来
